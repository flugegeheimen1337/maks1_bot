# Бот анкетирования «Практика»

Telegram-бот собирает короткую анкету из 6 вопросов и передаёт заявку куратору. Он не подбирает метод, не ставит диагноз и не ведёт консультацию: это предварительный шаг, чтобы куратор увидел запрос, формат, бюджет и удобное время.

## Как устроена анкета

1. Приветствие и согласие на обработку данных.
2. Основной запрос — одна тема, без уточняющих веток.
3. Короткий комментарий, его можно пропустить.
4. Опыт терапии.
5. Формат. Для «Онлайн» и «Не принципиально» бот спрашивает часовой пояс.
6. Бюджет.
7. Удобное время, можно отметить несколько окон.
8. Проверка ответов. «Изменить ответы» возвращает к первому вопросу и сохраняет уже введённое.
9. Отправка. Если у человека нет @ника, бот предлагает добавить его или ответить в этом же чате.

Кнопки встроены в сообщение, и бот правит его на месте. «Назад» на вопросах стоит отдельным нижним рядом. `/start` в любой момент начинает анкету заново. Незавершённый черновик живёт в Redis 24 часа. Отправленная заявка остаётся в базе.

После финального экрана обычные сообщения пересылаются в чат заявок с пометкой «Дополнение к заявке». Текст «Отзываю согласие» сразу удаляет заявки и ответы этого человека.

## Запуск

Нужны Python 3.11+ и Redis.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Заполните `.env`: токен BotFather, id закрытого чата заявок, id администраторов и операторов, данные оператора для текста согласия. Затем:

```bash
python -m bot
```

Либо через Docker, когда `.env` уже заполнен:

```bash
docker compose up --build
```

В Docker Redis доступен боту по адресу `redis://redis:6379/0`, его подставляет compose. Каталог `data/` хранит файл заявок.

Добавьте бота в закрытый чат и разрешите ему писать. Чтобы узнать id чата, можно временно переслать сообщение из него боту `@userinfobot` или посмотреть id в клиенте. Id группы обычно отрицательный.

Перед запуском разместите текст согласия по постоянной ссылке и укажите её в `PRIVACY_URL` и в описании бота у BotFather. Пока имя, паспорт и почта оператора пустые, на экране согласия остаются плейсхолдеры.

`RESPONSE_TIME` подставляется в финал вместо «[срок]». По умолчанию это «рабочего дня»: «В течение рабочего дня мы напишем вам…».

## Роли

Пишите команды боту в личку.

| Команда | Администратор | Оператор |
| --- | --- | --- |
| `/apps` список с фильтрами по дате, теме и статусу | да | да |
| `/app 12` карточка | да | да |
| `/find ник` или `/find 123` | да | да |
| смена статуса: новая, в работе, закрыта | да | да |
| `/stats` отвал по экранам | да | да |
| `/export` и кнопка CSV | да | нет |
| `/delete 12` и `/delete user 123456` | да | нет |

CSV открывается в Excel: кодировка UTF-8 с BOM, колонки разделены точкой с запятой.

Удаление в боте происходит сразу. В журнал пишется, кто удалил данные и сколько заявок стёрто; сами ответы в журнал не попадают. Telegram ID в журнале остаётся как отметка о факте удаления. Сообщения в чате куратора бот тоже пытается убрать.

Отвал считается так: сколько людей открыли экран и не дошли до следующего. Часовой пояс не обязателен для всех, поэтому уход с экрана формата считается только если человек не дошёл ни до пояса, ни до бюджета.

## Что хранится

В Redis — только текущий черновик, 24 часа.

В SQLite:

- заявка: ник или «нет никнейма», id, имя, время согласия, ответы, статус, время отправки;
- дополнения после финала;
- по одному заходу на экран для каждой сессии;
- журнал удалений, смены статуса и выгрузок.

Поля профиля, подтипа, пола специалиста и автоматические флаги не собираются и не вычисляются.

Карточка куратору выглядит так:

```text
НОВАЯ ЗАЯВКА · 18.11.2026, 20:14

КЛИЕНТ: @username (Имя Фамилия) · TZ: UTC+3
ЗАПРОС: Тревога и панические атаки
КОММЕНТАРИЙ: Трясёт перед выступлениями, стало мешать работе
ОПЫТ: Был, не помогло
ФОРМАТ: онлайн · 5 000–8 000 ₽
ВРЕМЯ: будни после 18:00, выходные
НОМЕР: 12
```

Строки часового пояса и комментария нет, если человек их не указал. Без ника вместо `@username` будет «без никнейма, отвечать через бота, ID: …». Время в карточке показывается в `CURATOR_TZ`, по умолчанию Москва. Номер заявки добавлен последней строкой, чтобы по нему менять статус.

Комментарий длиннее 500 символов не обрезается: бот просит сократить текст. На экране без ника кнопка называется «Я добавил(а) никнейм», и текст экрана ссылается на неё.

## Проверка

```bash
pip install -r requirements-dev.txt
pytest
```

Тесты покрывают переходы анкеты, карточку куратора, лимит текста, отзыв согласия, фильтры базы и роли. Живой Telegram и Redis для них не нужны.

## Перед боевым запуском

Это уже не часть кода, а то, что стоит закрыть отдельно:

- подать уведомление в Роскомнадзор до начала обработки;
- вписать в согласие реальные ФИО, паспорт и почту;
- подтвердить текст согласия и статус оператора у юриста;
- не обещать человеку в переписке метод или диагноз: бот для этого не предназначен.
